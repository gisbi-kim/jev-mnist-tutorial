06 / API 공통 언어

state는 판단할 자료, questions는 판단할 기준입니다

예를 들어 ‘비밀번호 재설정 메일이 도착하지 않는다’는 문의가 들어왔다고 합시다. 이것이 state입니다. 어느 팀이 맡을지, 장애 가능성이 있는지, 업무 영향이 얼마나 큰지를 questions에 담습니다. 질문의 ID는 직접 정합니다.

질문 타입질문의 모양응답에서 읽을 값

score 1.4는 ‘정답일 확률 140%’가 아닙니다

세 단계가 있으면 단계 번호는 0·1·2입니다. 확률이 0.1·0.4·0.5라면 점수는 0 × 0.1 + 1 × 0.4 + 2 × 0.5 = 1.4입니다. 단계 위치의 가중 평균이므로 소수가 될 수 있습니다. 등급 설명이 달라지면 같은 1.4의 의미도 달라집니다.

① 먼저 질문을 정의합니다

공통 예제 · Python
state = "I cannot sign in because the password reset email never arrives."
questions = {
    "route": {
        "type": "choice",
        "instructions": "Select the team best suited to resolve this request.",
        "criteria": {
            "account": "Sign-in, account access and password recovery",
            "payment": "Charges, receipts and payment methods",
            "other": "Requests outside account access and payments"
        }
    },
    "access_issue": {
        "type": "noul",
        "instructions": "The user is unable to access their account."
    },
    "impact": {
        "type": "score",
        "instructions": "Assess how much the issue blocks the user's work.",
        "criteria": [
            "Work can continue without any interruption",
            "Some work is blocked but an alternative is available",
            "The user cannot proceed and no alternative is stated"
        ]
    }
}

선택지 ID는 코드가 읽을 값이고, 설명은 모델이 의미를 판단할 기준입니다. ‘1, 2, 3’만 적기보다 각 단계가 어떤 상황인지 설명하는 편이 좋습니다. 위 영어는 예제 입력이며 한국어 설명문과는 별개입니다.

② Jev REST API로 보냅니다

앞의 state·questions에 이어서 실행
import os
import requests

response = requests.post(
    "https://api.typesafe.ai/v1/systemone",
    headers={"Authorization": "Bearer " + os.environ["TYPESAFE_API_KEY"]},
    json={"model": "jev-latest", "state": state, "questions": questions},
    timeout=30,
)
response.raise_for_status()
result = response.json()
route = result["answers"]["route"]
print(route["choice"], route["probabilities"])
print(result["answers"]["access_issue"]["noul"])
print(result["answers"]["impact"]["score"])

requests.post(..., json=...)가 JSON 직렬화와 Content-Type 설정을 처리합니다. 결과는 answers 아래에 요청한 질문 ID로 돌아옵니다. jev-latest는 바뀔 수 있는 별칭이므로 실험 기록에는 응답의 model 값도 남기고, 재현이 필요하면 계정에서 제공되는 고정 버전을 선택하세요. HTTP 요청·응답 출처 ↗

SDK는 TYPESAFE_API_KEY 환경변수를 읽고 타입이 있는 응답 객체를 반환합니다. HTTP의 딕셔너리 접근과 SDK의 속성 접근을 섞지 마세요. 기본 재시도 정책도 제공합니다. 클라이언트 명세 ↗

08 / 직접 모델 학습하기

Unsloth에서는 Python 객체를 직접 다룹니다

여기부터는 웹 서버에 JSON을 보내는 API가 아닙니다. 내 컴퓨터 메모리에 모델을 올리고 학습하는 함수입니다. 아래 표와 코드는 최신 문서의 변화를 섞지 않도록, 이 저장소에 보존된 실험 당시 구현을 기준으로 설명합니다.

호출중요한 인자결과와 역할

gold는 채점용 정답입니다. 실제 데이터에서는 이미지의 정답 숫자와 현재 숫자를 비교해 계산합니다. 위 한 줄만으로 일반화 성능을 학습할 수는 없습니다. 학습·검증·보정·테스트를 나눌 때는 같은 그림에서 만든 여러 현재 상태가 서로 다른 split으로 흩어지지 않도록 이미지 단위로 나눕니다.

학습 → 보정 → 저장의 순서

다음은 흐름을 보여주는 코드입니다. train_rows와 calibration_rows는 앞 형식으로 준비된 서로 다른 이미지의 목록이라고 가정합니다. CUDA·BF16을 지원하는 이 실험의 환경을 전제로 하며, 완전한 실행 절차와 패키지 버전은 재현 안내를 따릅니다.

설명용 학습 골격 · GPU 학습을 자동 실행하지 않습니다
from unsloth import FastDecisionModel, DecisionTrainer
import torch
from transformers import TrainingArguments

model, processor = FastDecisionModel.from_pretrained(
    model_name="unsloth/Qwen3.5-0.8B",
    max_seq_length=1024,
    load_in_4bit=True,
    dtype=torch.bfloat16,
)
model = FastDecisionModel.get_peft_model(
    model, r=16, lora_alpha=16, lora_dropout=0
)
items, report = FastDecisionModel.build_dataset(train_rows, processor, model)
cal_items, cal_report = FastDecisionModel.build_dataset(
    calibration_rows, processor, model
)
for check in (report, cal_report):
    if check["skipped"] or check["truncated"]:
        raise ValueError(check)
if not items or not cal_items:
    raise ValueError("학습·보정 자료가 비어 있습니다.")

FastDecisionModel.for_training(model)
trainer = DecisionTrainer(
    model=model,
    processing_class=processor,
    train_dataset=items,
    head_learning_rate=1e-3,
    args=TrainingArguments(
        output_dir="work/checkpoints",
        per_device_train_batch_size=32,
        gradient_accumulation_steps=1,
        max_steps=600,
        learning_rate=2e-4,
        bf16=True,
        report_to="none",
    ),
)
trainer.train()
FastDecisionModel.for_inference(model)
metrics = FastDecisionModel.calibrate(model, processor, cal_items, batch_size=1)
model.save_pretrained("work/mnist-adapter")

학습률 두 개가 보이죠. learning_rate는 기반 모델 쪽 학습 대상에, head_learning_rate는 판단부에 사용됩니다. 위 골격은 원문의 스케줄러·콜백·중간 검증 설정을 모두 복제하지는 않았습니다. 원문 수치를 재현하려면 train.py와 저장 설정을 함께 사용해야 합니다.

10 / 이해에서 실험으로

벤치마크와 API를 읽을 때 기억할 것

  1. 속도는 무엇을 포함했는지 봅니다.

    모델 계산 시간, 네트워크 왕복, 웹페이지 가져오기까지 포함한 시간은 서로 다릅니다. 제조사별 숫자를 그대로 줄 세우면 비교가 어긋날 수 있습니다.

  2. 좋은 형식과 좋은 판단을 나눠 봅니다.

    항상 유효한 선택지가 나온다는 것은 연결하기 편하다는 장점입니다. 그 선택지가 맞는지, 틀렸을 때 확률도 낮은지는 별도로 확인합니다.

  3. 업무의 작은 결정부터 평가합니다.

    ‘모든 문의를 처리하라’보다 ‘세 팀 중 어디에 보낼까?’처럼 범위가 분명한 질문부터 시작합니다. 그 다음 실제 정답과 혼동 사례, 확률, 응답 시간을 함께 기록합니다.
