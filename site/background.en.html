01 / Big picture

Jev·Clef is the model, Unsloth is the implementation and teaching tool

nameWhat is it?Relationship to this tutorial

Basis: Introduction to TypeSafe · Clef model card · About Unsloth

It is not a structure that calls three things one after another.

The MNIST experiment on this site does not call the Jev server. A Qwen-base model trained directly with Unsloth looks at the picture and chooses an action. It is not an evaluation of the completed Clef model deployed by Cloudflare. actual model code

How is it different from a typical classifier?

Traditional classifiers usually output categories determined during training. The decision model covered here is Including the question to be judged and the meaning of the options in each requestThis is the feature. For example, in ‘Which team should I send it to?’, the option is given as ‘Payment/Technology/Other’, or in other requests, change it to ‘Archive/Review/Delete Candidate’. It must be separately verified whether the new options are judged well.

It may look similar to LLM, which outputs JSON. The difference lies in the JSON file format itself. Do you sequentially generate free sentences internally, or do you score points directly on the accepted answers?It is in Even an answer that is correct in type may be wrong in content. So what should we compare first?

  • To add judgment function without running the server: Hosting APIs such as Jev·OpenAI Decisions·Microsoft-Decision-1·GLiDE·Mercury Decide are compared using the same evaluation data.
  • To start with small text classification on my computer: You can start by looking at encoder models such as Laya·GLiNER2.5-Decide. Check whether Korean language is supported and actual Korean accuracy separately.
  • To pick an action by looking at an image like in this MNIST experiment: Check the corresponding version of Clef·d1·H2O-Lightning·pplx-Decider that supports image input, and check the support range of Unsloth or Strands for direct learning.
  • If you need up-to-date web information to help you decide: Like Parallel, compare services including search. Comparing model inference times alone misses differences across tasks.

Can I replace it by just changing the API address?

This isn't always the case. Jev series state / questions / nouland OpenAI's input / questions / predicateAlthough the meaning is similar, the JSON structure is different. Cloudflare also has a different outer response wrapper. Request transformation, response transformation, error handling, probability threshold reassessmentis required. Don’t just look at the word ‘compatible’ and treat the numbers as having the same meaning.

In particular, Perplexity explains that even if you send an old model name in the API, you can connect to the new version. If it's a repro experiment, you should check the change history and actual delivered version, not just the name. Version/Charging Rules ↗

Are general LLM/classifier/router alternatives?

yes. Alternative methods include requesting structured output from general LLMs such as GPT·Claude·Gemini, learning the Qwen·Llama series directly, or using a BERT classifier. However, not all are ‘dedicated decision models’ in this table. First decide whether you need a free explanation, just a fixed category, or whether the options will change with each request.

Distribution APIs like OpenRouter and learning tools like Unsloth are also distinct from the models themselves. Even though the model list may seem large, there are cases where multiple services provide the same weights.

Four criteria for reading tables

04 / Understanding Clef

Clef is an open model that ‘scores the options for each question’

After the Qwen-base model reads the input, Clef joint schema headIt is a structure that calculates the score of the question and the allowed options. Convert the score for each question into a probability. There is no need to create free descriptive sentences first.

In the confirmed model card, Clef is based on Qwen3.8-27B, and the weight and judgment part implementation is released as Apache-2.0. A smaller variant is Clef-flash. You can check the exact model configuration and conditions at the time of use based on each model card. Model Card ↗

Distinguish between ‘Clef method head’ and ‘Cloudflare/Clef complete model’.

Our experiments attached a new judge unit to the smaller Qwen3.5-0.8B. Using the structure does not mean that the pretraining results, performance, and calibration characteristics of the Cloudflare model are transferred as is.

06 / API common language

The state is the data to be judged, and questions are the standards to be judged.

For example, let’s say you receive an inquiry saying, ‘The password reset email has not arrived.’ This is stateIt is. Which team will be in charge, whether there is a possibility of failure, and how big the impact will be on the business. questionsPut it in . You decide the ID of the question yourself.

Question typeshape of the questionValue to read from response
choiceOne of several options. criteriais option ID → descriptionchoice, by choice probabilities, confidence
noulA yes/no question such as ‘Is this an account access issue?’noul: Probability of yes, 0~1
scoreList of steps described from low to highscore, step by step probabilities, legend, confidence

Specifications by type: Choice · Noul · Score

score 1.4 is not ‘140% chance of being correct’

If there are three stages, the stage numbers are 0·1·2. If the probability is 0.1·0.4·0.5, the score is 0 × 0.1 + 1 × 0.4 + 2 × 0.5 = 1.4It is. It can be a decimal number since it is a weighted average of the step positions. As the grade description changes, the meaning of the same 1.4 also changes.

Probability and confidence are not the same field

The probability of the ‘Technical Team’ option and the confidence of the entire response are read separately. In particular, Unsloth's Laya serving and Jev have different confidence calculations, so the existing threshold should not be transferred as is. You will need to reassess from the same work materials. Differences in compatible APIs ↗

Are there types like Image and Box?

The current TypeSafe document also has a separate Box type that inputs an image and returns the area within the image. As of confirmation date, both are experimental features and require the TypeSafe-Danger-Zone-Images: true header to be used. The three types above are the common introductory scope of this article. You must check the dedicated documentation for image transmission formats and support models, and Python's PIL object cannot be directly inserted into HTTP JSON. Images · Box

In TypeSafe, 401 is authentication, 422 is validation error, such as question format. 429 is a call volume limit, and 529 is a temporary overload, so increase the interval and retry. The REST example above is minimal and does not implement automatic retries. Error codes and retries ↗

from unsloth import FastDecisionModel, DecisionTrainer
import torch
from transformers import TrainingArguments

model, processor = FastDecisionModel.from_pretrained(
    model_name="unsloth/Qwen3.5-0.8B",
    max_seq_length=1024,
    load_in_4bit=True,
    dtype=torch.bfloat16,
)

    model, r=16, lora_alpha=16, lora_dropout=0
)
items, report = FastDecisionModel.build_dataset(train_rows, processor, model)
cal_items, cal_report = FastDecisionModel.build_dataset(
    calibration_rows, processor, model
)
for check in (report, cal_report):
    if check["skipped"] or check["truncated"]:
        raise ValueError(check)
if not items or not cal_items:
    raise ValueError("학습·보정 자료가 비어 있습니다.")

FastDecisionModel.for_training(model)
trainer = DecisionTrainer(
    model=model,
    processing_class=processor,
    train_dataset=items,
    head_learning_rate=1e-3,
    args=TrainingArguments(
        output_dir="work/checkpoints",
        per_device_train_batch_size=32,
        gradient_accumulation_steps=1,
        max_steps=600,
        learning_rate=2e-4,
        bf16=True,

    ),
)
trainer.train()
FastDecisionModel.for_inference(model)
metrics = FastDecisionModel.calibrate(model, processor, cal_items, batch_size=1)
model.save_pretrained("work/mnist-adapter")

10 / From understanding to experimentation

Things to remember when reading benchmarks and APIs

  1. Speed see what's included.

    The times including model calculation time, network round trip, and web page retrieval are different. If the numbers for each manufacturer are lined up as is, the comparison may be inconsistent.

  2. Let's share good format and good judgment.

    The advantage of always having valid options is that it is easy to connect. We separately check whether the choice is correct and whether the probability of being wrong is low.

  3. Evaluate small business decisions first.

    Rather than ‘Handle all inquiries,’ start with questions with a clear scope, such as ‘Which of the three teams should I send to?’ The actual correct answer is then recorded along with confusion cases, probabilities, and response times.

This MNIST experiment is an example of seeing those small decisions with your own eyes. Given a picture and the current state, you can see how the results of one choice and repeated execution change.
